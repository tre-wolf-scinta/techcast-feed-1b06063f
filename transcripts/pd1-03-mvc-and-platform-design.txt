Salesforce MVC: Which Layer Is It?

Where does a page layout belong in Salesforce's version of Model View Controller, MVC for short? Plenty of developers say Model, because the layout lives under the object. The exam counts that as wrong, and it asks this kind of question more than once.

Say Priya gets a ticket. Sales reps need a Discount Percent field on Opportunity, a warning when it passes 20 percent, and a button that sends the deal to a manager for approval. Before she builds anything, think of a restaurant kitchen. The pantry holds the ingredients, the plate is what the diner actually sees, and the chef decides what to pull from the pantry and how to cook it. On the platform, the pantry is the Model, the plate is the View, and the chef is the Controller.

Priya starts in the pantry. She creates a custom field called Discount Percent on the Opportunity object. Objects, fields, and the relationships between them are the Model, because that is where the data is defined and stored. Next she drags the field onto the Opportunity page layout. That feels like object setup, but a layout only controls what a user sees, so it is View. Then she builds a Visualforce page for the approval button. The page itself is View. She points it at the standard controller for Opportunity, which the platform generates for free and which already knows how to load, save, and delete the record. That standard controller is Controller logic she never wrote. When she needs the 20 percent warning and the approval request, she adds an Apex controller extension, and that custom Apex is Controller too. A screen flow launched from the same button would also be Controller, just declarative instead of coded.

Now her team asks her to rebuild the page as a Lightning web component, and here is where the clean three way split gets fuzzy. The exam will tell you a Lightning component belongs to View, and that is the answer to give. But open the bundle. There is a template of markup, which is clearly view, and a JavaScript class that holds state, handles the button click, and calls an Apex method marked Aura Enabled on the server. Aura components go further and literally name their client side JavaScript file a controller. So the Lightning Component Framework is not a strict MVC implementation. It is a component based framework, where each component packages its own slice of markup and logic, and the MVC layering only holds at the platform level: components on the page, Apex behind them, objects underneath. If a question asks what kind of framework it is, answer component based, not MVC.

The rule of thumb: if it stores or defines data it is Model, if a user sees it it is View, if it decides what happens it is Controller, and a Lightning component is a self contained bundle that the exam files under View.
